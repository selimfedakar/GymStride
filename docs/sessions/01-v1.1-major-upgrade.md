## 1. Crash reporting + analytics

**What:** New `lib/analytics.ts` — one provider-agnostic surface (`track`, `identify`, `resetUser`,
`captureError`, `captureMessage`, `addBreadcrumb`, `wrapRoot`). Sentry for crashes, PostHog for the
funnel. A typed `AnalyticsEvent` union keeps event names honest.

**Why:** v1.0 flew blind — zero crash/funnel visibility on a live app. The plan called this the single
most critical gap; every later decision needs this data.

**How:** `initMonitoring()` runs at root-module scope in `app/_layout.tsx`; the root component is wrapped
via `wrapRoot()`. On auth the user is `identify()`-ed and `app_opened` fired. **Silent error swallows were
replaced with `captureError`** across `_layout`, `profile`, `messages`, `chat`, `log`, discovery, blocks,
events — the ".catch(() => null)" black holes are gone.

**Key design:** everything is **guarded by env vars** — with no DSN/key the calls are no-ops, so dev and
the simulator run without any keys. Metro config now uses `getSentryExpoConfig` for source-map upload.

**Decision log:**
- *PostHog vs Amplitude vs Firebase* → PostHog: generous free tier, no Google dependency, session +
  funnel in one SDK.
- *Provider-agnostic wrapper vs direct SDK calls in screens* → wrapper, so swapping/removing a provider
  is a one-file change and screens stay clean.

## 2. Streaks (made visible)

**What:** `get_my_streak()` RPC (migration 024) → `StreakCard` (Log hero) + `ActivityStrip` (Profile).
Current streak, longest, this-week count, 7-day dot strip.

**Why:** the server already computed streaks for badges (`003_rls_policies.sql`) but nothing was ever
shown — a retention hook left on the floor.

**How:** SECURITY DEFINER, runs for `auth.uid()` only (no `profile_id` param → can't read others').
Streak day = any UTC day with ≥1 log; "current" only counts if the latest logged day is today/yesterday.

## 3. Update location anytime

**What:** Shared `lib/location.ts` (GPS → reverse-geocode → PostGIS point, with manual-city fallback).
"Use my current location" + manual entry added to Edit Profile; `updateMyLocation()` query.

**Why:** location was written **once** at onboarding and never again — a user who moved cities had
permanently broken discovery. Serious gap.

**How:** onboarding's inline logic was extracted into `lib/location.ts` and **both** onboarding and Edit
now call it (single source of truth). `LocationPermissionError` lets callers offer the manual path.

## 4. Block user (Apple Guideline 1.2)

**What:** `blocks` table + `block_user`/`unblock_user`/`get_my_blocked_ids` RPCs (migration 025). A block
hides both users in discovery, in conversations, and cancels pending requests between them. New
**Blocked Users** management screen (`app/profile/blocked.tsx`).

**Why:** v1.0 had report but no block — an App Store risk for a UGC app and a real safety gap.

**How:** discovery RPCs and `get_my_conversations` rewritten with a `NOT EXISTS (blocks …)` filter (both
directions); Messages also filters incoming requests client-side (belt + suspenders). `block_user`
additionally prunes pending requests so nothing dangles.

## 5. Chat reliability

**What / root causes fixed:**
- **Message double-render** — a sent message was appended locally *and* re-arrived via realtime.
  → `appendUnique()` dedupes by id in both chat and event chat.
- **Silent message loss** — `setText('')` ran *before* the network call; a failed send ate the text.
  → text is cleared optimistically but **restored on failure**, with `captureError`.
- **Realtime fan-out** — `useUnreadCount` and the Messages tab subscribed to **every** message insert
  system-wide (a hard scaling wall). → both now scope the subscription with
  `conversation_id=in.(…my conversations…)`.

## 6. Cleanup

Removed dead `logWorkout()` + its unused import, the empty `app/tabs/` dir, and `metro.config.js.bak`.
Added migration 026 seeding the `badges` catalogue (was hand-populated from the dashboard → non-reproducible;
now idempotent `ON CONFLICT (name) DO NOTHING`). `.gitignore` now covers the local mockups/scratch files.

## 7. GymStride Pro (RevenueCat)

**What:** `lib/purchases.ts` (configure/isPro/offerings/purchase/restore), `store/pro.ts` (global
entitlement), `app/paywall.tsx` (benefits, packages, purchase, restore, StoreKit legal copy). The
free-tier **5-requests/day cap now routes to the paywall**; a Pro card/status sits on Profile.

**Why:** zero monetization existed. The daily request cap was already a natural paywall hook.

**How:** guarded by the platform API key — no key ⇒ `isPro()` false, offerings empty, app unaffected.
Advanced discovery filters (experience/pace) are Pro-gated in the UI; same-campus stays free.

## 8. Apple Health import

**What:** `lib/health.ts` imports running workouts → `workout_logs` (migration 027 adds `source` +
`external_id` with a unique partial index so re-imports don't duplicate). Button on the Log tab (iOS only).

**How:** defensive by design — off-device it short-circuits; the exact `@kingstinct` API is probed at
runtime so a version mismatch degrades to "0 imported" instead of crashing. Runs are classified
(long/short/sprint) from distance + pace.

## 9. Discovery map

**What:** `get_buddy_pins()` (migration 028) returns **coordinates snapped to 2 decimals (~1.1 km cells)** —
density and rough area without exposing precise location. `BuddyMap` (react-native-maps) with a list↔map
toggle on Gym + Running.

**Decision:** a *separate* fuzzed-pins RPC instead of adding coordinates to the main discovery output —
keeps precise locations off the main path entirely.

## 10. Progress charts

**What:** `get_my_progress()` (migration 029) → last 8 weeks volume + month totals. `ProgressChart`
(react-native-svg) on Profile with a Sessions/Run-km toggle.

**Decision:** hand-rolled SVG bars over victory-native/skia — far lighter, no heavy new chart dependency.

## 11. Filters + multi push token

**What:** discovery RPCs gained `p_same_university` (free) + `p_experience`/`p_max_pace` (Pro) — migration 030.
`push_tokens` PK moved from `profile_id` to `(profile_id, token)` (migration 031) so multi-device users get
notified on every device; the notify Edge Function now fans out to all tokens; the client releases a token
from a previous account on re-login.

## 12. Group events

**What:** `events` + `event_participants` + `event_messages` (migration 032) with capacity-checked
`create_event`/`join_event`/`leave_event` and `get_nearby_events` (upcoming, radius, block-aware). New
**Events tab** (list + create sheet) and `app/event/[id]` (detail + participant avatars + **group chat**).

**Decision:** event chat uses its own `event_messages` table rather than reusing 1:1 `conversations` —
so `get_my_conversations` (which assumes exactly one "other" participant) stays simple and correct.

## 13. Widget + matching quality

**Widget:** `targets/widget/` (expo-apple-targets) — a SwiftUI streak widget reading shared app-group
defaults; `lib/widget.ts` writes the streak from JS and reloads the widget after each Log refresh.
App-group entitlement added to `app.json`.

**Matching quality:** `training_today` DATE + `set_training_today()` (migration 033) — a self-expiring
"🔥 Training today" availability flag, toggled on Profile and surfaced on public profiles alongside a
"⚡ Same level" compatibility hint. `preferred_time` (already in schema, never collected) is now captured
in Edit Profile and shown on public profiles.
