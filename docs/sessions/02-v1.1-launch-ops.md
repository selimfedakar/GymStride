## 2. Bug log — the build failed four times, each for a different reason

This is a textbook chain of native-layer integration failures. TypeScript was green the whole time;
none of these were detectable before the native toolchain ran.

### Round 0 (local): PostGIS migrations 028/032 — `type "geography" does not exist`
- **Root cause:** the new SECURITY DEFINER functions used `SET search_path = ''` (the project's
  injection-hardening convention), but on Supabase PostGIS lives in the `extensions` schema, so with
  an empty path the `GEOGRAPHY` type and `ST_*` functions don't resolve.
- **Fix:** geography-touching functions (`get_buddy_pins`, `create_event`, `get_nearby_events`) use
  `SET search_path = public, extensions`. Non-PostGIS functions keep `''`.
- **Lesson:** an empty search_path and PostGIS are mutually exclusive; pin `public, extensions` instead.

### Round 1: `@bacons/apple-targets` wouldn't even load
- **Symptom:** prebuild failed — `Cannot find module '@react-native/normalize-color'`; also
  `ExtensionStorage` missing from the package.
- **Root cause:** npm resolved apple-targets to **0.0.4** (ancient) and it was missing a transitive dep.
- **Fix:** upgrade to 4.0.7 + install `@react-native/normalize-color` as a devDependency.

### Round 2: `Could not find target 'GymStrideStreak' in project.pbxproj`
- **Root cause:** `targets/widget/expo-target.config.js` had `name: 'GymStride Streak'` (with a
  space) → Xcode target generated with a space; `app.json`'s
  `extra.eas.build.experimental.ios.appExtensions[0].targetName` said `GymStrideStreak`. EAS signs
  targets by the appExtensions name and couldn't find it.
- **Fix:** rename the target config to `GymStrideStreak`. The user-facing widget name comes from
  Info.plist, so nothing visible changed.

### Round 3: `value of type 'AnyMap' has no member 'isBigInt'`
- **Root cause:** `@kingstinct/react-native-healthkit` 9.0.11 is built against
  `react-native-nitro-modules` ^0.26.4; npm had installed 0.36.1 (peer says `*`), whose AnyMap C++
  API had changed.
- **Fix:** pin `react-native-nitro-modules@0.26.4`.
- **Lesson:** with Nitro-based libraries, treat the nitro-modules version as part of the library's
  ABI — check the library's *devDependency*, not its peer range.

### Round 4a: Sentry — `Auth token is required for this request`
- **Root cause:** the Sentry Expo plugin injects a source-map upload into the "Bundle React Native
  code and images" phase; it hard-fails without `SENTRY_AUTH_TOKEN`.
- **Fix:** org auth token created in Sentry, stored via
  `eas env:create --environment production --name SENTRY_AUTH_TOKEN --visibility secret`.

### Round 4b: Sentry — `One or more projects are invalid (400)`
- **Root cause:** the Sentry project had been created with the default slug `react-native`, while
  `app.json` declares `project: "gymstride"`.
- **Fix:** rename the project slug to `gymstride` in Sentry settings. The DSN is ID-based and
  unaffected.

## 3. Process change that paid for itself immediately

After round 2, every EAS attempt was preceded by a **local release build**:

```bash
xcodebuild -workspace ios/GymStride.xcworkspace -scheme GymStride -configuration Release \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

This caught round 4a locally (~10 min) instead of burning a ~25-minute EAS queue cycle, and proved
the whole native graph compiled before re-submitting. Rule going forward: **no `eas build` until the
local simulator Release build is green.**

(`SENTRY_DISABLE_AUTO_UPLOAD=true` makes the local build pass without the auth token; EAS has the
real token so uploads run there.)

## 4. Decision log

- **Nitro pin vs healthkit upgrade:** healthkit 14.x supports nitro 0.36 but is five majors ahead of
  the version `expo install` blessed for SDK 54; pinning nitro down was the smaller change. Revisit
  on the next Expo SDK bump.
- **Sentry token as EAS secret, not eas.json env:** the repo is public. The `EXPO_PUBLIC_*` keys in
  `eas.json` are client-side, ship in the binary anyway, and are write-only — acceptable. The auth
  token is a real secret and lives only in EAS.
- **Sentry project renamed rather than app.json edited:** keeps the org/project pair self-describing
  (`gymstride/gymstride`) and avoids touching committed config for a dashboard-side mismatch.
- **Pro products deferred:** paywall ships env-guarded with a graceful empty state; ASC subscription +
  RevenueCat offering is the next store-side task. Known Guideline 2.1 risk accepted.
